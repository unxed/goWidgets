# PLAN — showcase `zipgui` (GUI к zipper, эталон UX — WinRAR)

Постановка — unxed/goWidgets#30, решение о рамках — [ADR-0019](../adr/0019-showcase-zipgui.md).
Шаги идут по одному PR, чередуясь с планом pixy (`docs/pixy/`); одновременно открыт не больше
одного PR zipgui. Каждый шаг заканчивается комментарием в тикете: что и как попробовать.

## Границы

* Код — `showcase/zipgui` (отдельный модуль). Только `showcase/zipgui/engine` импортирует
  `github.com/unxed/zipper/archive`.
* Недостающее в zipper — тикет и PR в unxed/zipper; после выпуска тега zipper шаг zipgui
  поднимает версию в `showcase/zipgui/go.mod`.
* Новый контрол библиотеки — во всех бэкендах (headless, GTK, Qt 5/6, Win32, Cocoa; Web — где
  уже есть драйвер) либо capability-флаг и запасной путь в core. Пока контрол есть не везде,
  showcase работает на запасном пути.
* Локально — только `gofmt`. Сборка и тесты — в CI (`CI fast`, `CI gui`).

## Пробелы, найденные при разборе (20-10-2026)

### API zipper (`zipper/archive` v0.1.178)

| # | Нужно showcase | Что есть | Пробел |
|---|---|---|---|
| Z1 | Колонки Packed / CRC / Method, признак шифрования | `OpenFS` → `fs.FileInfo` (имя, размер, время, режим) | единая запись листинга: `archive.Entry{Name, Size, Packed, Modified, CRC32, Method, Encrypted, IsDir}` и функция листинга для zip / tar / 7z / rar (Packed = −1, где формат его не знает) |
| Z2 | Извлечь выделенное | `NewExtractor` извлекает всё | `Options.Include []string` — пути внутри архива, каталог включает поддерево |
| Z3 | Test | нет | проверка целостности без записи на диск, с `Progresser` и списком ошибок по файлам |
| Z4 | Режим «спрашивать» при перезаписи | `KeepOldFiles` / `KeepNewerFiles` / перезапись | обратный вызов на конфликт имён (заменить / пропустить / отменить) |
| Z5 | Отмена | `ctx` во всех `Extract` / `Archive` | проверить тестом в zipper, что отмена срабатывает между файлами, а не после всего архива |
| Z6 | Текущий файл в прогрессе | `CurrentFile()` у zip / tar / fallback, но не в интерфейсе | мелочь: интерфейс `CurrentFiler` в `archive` |

Уже есть и пробелом не является: прогресс (`Progresser.Written`, итог считается по листингу),
пароли (`Options.Password`, `IsPasswordError`), изменение zip и tar (`NewUpdater`: Append /
Remove; 7z и rar — нет, это capability в zipgui), форматы записи (`NewArchiver` по расширению).
Оговорка: `OpenFS` для tar создаёт индекс в кэше пользователя (`os.UserCacheDir()/f4/tar-indexes`).

## Шаги

Готовность каждого шага: PR влит с зелёными `fast`, `linux`, `windows`, `macos`; в тикете —
комментарий «что попробовать» со ссылкой на артефакт или способ сборки.

1. **ADR и каркас.** ADR-0019, этот план, вложенный модуль `showcase/zipgui` (окно: кнопка
   «Открыть…» и строка-сводка архива через `engine`), проверки модуля в `CI fast` и `CI gui`.
   Каркас входит в шаг, потому что PR только с документами CI не запускает вовсе
   (`paths-ignore`), а обязательные проверки нужны; заодно сразу проверены CGO, кросс-сборка и
   размер бинаря с zipper. *Готово:* модуль собирается на всех целях, бинарь < 25 МБ, тест
   `engine` создаёт zip и tar.zst через zipper и читает сводку.
2. **Эталон.** `docs/zipgui/REFERENCE.md`: главное окно, диалоги Add и Extract, прогресс, клавиши
   WinRAR; для каждого пункта — что умеет zipper, чего нет (Z1–Z6), что будет в каком шаге.
   Своими словами, без скриншотов эталона в репозитории. Код шага (чтобы шаг прошёл CI и был
   полезен): `engine.Formats()` — таблица форматов (чтение / запись / изменение / пароль) по
   `archive.DetectFormat` и `archive.NewUpdater`, тест сверяет её с REFERENCE. Необязательный
   `winrarref.yml` (триал под Wine) — только если лицензия триала позволяет и это не дороже часа.
   *Готово:* REFERENCE и `engine.Formats` влиты.
3. **API zipper.** Тикет в unxed/zipper с атомарным планом Z1–Z6 (по PR на пункт), первый PR —
   Z1 (листинг с метаданными), тег zipper выпущен. *Готово:* тикет заведён, Z1 влит, ссылка здесь.
4. **Окно со списком (только чтение).** Сначала библиотека (L1), подшагами по одному PR:
   4a. core: `Window.AddTable(columns []TableColumn) (*Table, error)`, `SetRows`, `Selected`,
       `Activated`, `HeaderClicked(col)`; headless-реализация и тест модели; capability
       `Caps.GridView`; запасной путь в core для бэкенда без таблицы — `ListBox`, строки
       которого склеены из колонок; ADR на контракт драйвера.
   4b. GTK (`GtkTreeView` + `GtkListStore`), 4c. Win32 (ListView, `LVS_REPORT`), 4d. Qt
       (`QTreeWidget`), 4e. Cocoa (`NSTableView`) — каждый со своим тестом в `*test` бэкенда и
       скриншотом в CI.
   4f. zipgui: открыть архив (аргумент и кнопка «Открыть…», чтение в горутине,
       `App.QueueUpdate`), корень архива в таблице Name / Size / Packed / Modified, сортировка по
       заголовку, каталоги сверху. *Готово:* скриншоты на всех бэкендах, тест модели списка
       (сортировка, каталоги сверху) в headless.
5. **Навигация внутри архива.** Enter / двойной щелчок по каталогу, строка `..`, строка пути
   (`Edit` только для чтения или `Label`), Backspace — вверх. Модель навигации — отдельный тип с
   тестами без UI. *Готово:* тесты навигации, скриншот.
6. **Extract To.** Панель «Извлечь» в главном окне (путь + «Обзор…» через `SelectFolder`, режим
   перезаписи `ComboBox`: заменять / пропускать / спрашивать — последний только после Z4),
   извлечение выделенного (Z2) или всего в горутине; прогресс — сначала текстом
   «45 % — имя файла» в строке состояния и кнопка «Отмена» (`context.Cancel`), затем L2.
   *Готово:* интеграционный тест извлечения zip и 7z во временный каталог, тест отмены.
7. **Test.** Кнопка «Проверить»: Z3 с прогрессом и списком ошибок. *Готово:* тест на исправном и
   испорченном архиве (испорченный — байт, перевёрнутый в данных файла).
8. **Add / новый архив.** Панель или окно (L3) «Добавить»: имя архива, формат (zip / 7z /
   tar.zst / tar.gz / tar.xz), уровень, пароль. *Готово:* тест «создать → открыть → сверить
   список».
9. **Изменение архива.** Удалить выделенное и добавить файлы в существующий zip / tar
   (`NewUpdater`); для 7z и rar кнопки неактивны с подсказкой. *Готово:* тест.
10. **Пароли.** Запрос пароля (L4) при `IsPasswordError` на открытии и извлечении. *Готово:* тест
    с зашифрованными zip и 7z.
11. **Drag-and-drop.** Сначала приём файлов в окно (L5: событие drop с путями в драйверах
    Win32 / GTK / Qt / Cocoa) → «Добавить»; вынос из окна наружу — capability-флаг, по
    умолчанию выключен. *Готово:* тест там, где CI позволяет (xdotool под Xvfb), иначе ручной
    сценарий в комментарии.
12. **Info и Find.** Сводка (число файлов, размеры, степень сжатия, формат, шифрование) и поиск
    по маске имени внутри архива. *Готово:* тест и скриншот.

После шага 12 — сверка с REFERENCE.md, расхождения — отдельными тикетами.

## Подводные камни

* Вложенный модуль: корневые `go vet ./...` / `go test ./...` его не видят — каждую новую
  проверку для zipgui добавляй в CI явно (`working-directory: showcase/zipgui`).
* `replace` библиотеки (`purego => pureffi`) обязан стоять и в `showcase/zipgui/go.mod`.
* `go.sum` вложенного модуля правится по выводу шага `go mod tidy -diff` в `CI fast`.
* Размер бинаря проверяет `CI fast`; при превышении сначала попробовать
  `-tags tarindex_simple` (индекс tar без SQLite), потом — разговор в тикете.
* Индекс tar, который `OpenFS` держит в кэше (путь — по абсолютному имени архива), после
  изменения архива (`NewUpdater`) не перестраивается: `tar.NewFS` (unxed/tar v0.1.137) строит
  индекс, только если его файла нет, и листинг показывает старое содержимое. Пункт для тикета
  zipper (шаг 3); до исправления после изменения читать архив со свежим `Options.IndexPath`
  (так делает тест `engine.TestFormatsMatchZipper`; шаг 9).
* Docs-only PR не запускает CI: шаг без кода не может получить обязательные проверки.
