# REFERENCE — что умеет эталон и что из этого будет в `zipgui`

Эталон UX — WinRAR (по справке rarlab.com и поведению программы). Здесь — описание своими
словами, без текста справки и без скриншотов. Для каждого пункта: есть ли нужное в zipper
(`zipper/archive` v0.1.179; пробелы Z1–Z6 и L1–L6 — в [PLAN.md](PLAN.md)) и в каком шаге плана
пункт появится в `zipgui`.

## Главное окно

Одно окно — файловый список в духе проводника: архив открывается как папка, внутри него можно
ходить по каталогам. Сверху панель команд крупными кнопками, под ней строка пути, ниже список,
внизу строка состояния.

| Пункт эталона | Что делает | zipper | Шаг |
|---|---|---|---|
| Панель команд: Add | добавить файлы в архив (новый или открытый) | есть: `NewArchiver`, `NewUpdater` | 8, 9 |
| Extract To | извлечь выделенное или всё в выбранную папку | всё — есть; выделенное — нет (Z2) | 6 |
| Test | проверить целостность без записи на диск | нет (Z3) | 7 |
| View | показать файл из архива во встроенном просмотрщике | чтение через `OpenFS` есть | вне 12 шагов |
| Delete | удалить выделенное из архива | есть для zip и tar (`Updater.Remove`) | 9 |
| Find | искать по маске имени (и по тексту) внутри архива | листинг через `OpenFS` есть | 12 |
| Info | сводка: число файлов, размеры, степень сжатия, формат, шифрование | есть: размеры, Packed и шифрование — `archive.List` (Z1, v0.1.179) | 12 |
| Repair | восстановить повреждённый архив | для RAR — запись восстановления; в zipper есть par2, но не как «починить архив» | вне 12 шагов |
| Строка пути | где внутри архива мы сейчас; выпадающий список уровней вверх | — (модель навигации в zipgui) | 5 |
| Колонки Name, Size, Packed, Type, Modified, CRC32 | сортировка щелчком по заголовку, повторный щелчок — обратный порядок; каталоги сверху | Name, Size, Packed, Modified, CRC32, метод — есть (`archive.List`, Z1, v0.1.179); таблица в библиотеке — нет (L1) | 4 |
| Строка `..` в начале списка | подняться на уровень вверх | — | 5 |
| Строка состояния | сколько выделено и общий размер выделенного; общий итог по каталогу | — (считает zipgui) | 4, 12 |
| Меню File / Commands / Tools / Options | те же команды и настройки | — (меню в библиотеке нет, L6) | вне 12 шагов: команды — кнопками |
| Перетаскивание | файлы из проводника в окно — добавить; из окна наружу — извлечь | — (L5) | 11 |

## Диалог «Добавить» (имя архива и параметры)

| Пункт эталона | zipper | Шаг |
|---|---|---|
| Имя архива с кнопкой «Обзор…» | есть (имя файла → формат по расширению) | 8 |
| Формат архива (у эталона RAR, RAR4, ZIP) | zip, 7z, tar.zst, tar.gz, tar.xz (таблица форматов ниже); RAR zipper не пишет | 8 |
| Метод сжатия: от «без сжатия» до «максимальный» | `Options.Method`, `Options.Level` | 8 |
| Разбить на тома заданного размера | `Options.SplitSize` (tar), тома zip — чтение | вне 12 шагов |
| Режим обновления: добавить с заменой, обновить, освежить, синхронизировать | `NewUpdater` (Append / Remove) для zip и tar | 9 |
| Опции: удалить файлы после упаковки, создать SFX, непрерывный (solid) архив, запись восстановления, проверить после упаковки, заблокировать архив | solid для 7z (`Options.Solid`), блокировка (`Options.Lock`); остальное — нет | вне 12 шагов (кроме solid — 8) |
| Пароль (с подтверждением и показом символов) | `Options.Password`; маска ввода в библиотеке — нет (L4) | 10 |

| Пункт эталона | zipper | Шаг |
|---|---|---|
| Папка назначения: строка и дерево папок справа | есть (`chroot` извлечения) | 6 (строка и «Обзор…» через `SelectFolder`; дерево — нет) |

## Окно прогресса

Отдельное окно: имя текущего файла, полоса по файлу и общая полоса, прошедшее и оставшееся время,
кнопки «Фоном», «Пауза», «Отмена».

| Пункт эталона | zipper | Шаг |
|---|---|---|
| Общий процент | `Progresser.Written`, итог — по листингу | 6 (текстом в строке состояния), затем L2 |
| Текущий файл | `CurrentFile()` есть, но не в интерфейсе (Z6) | 6 |
| Отмена | `ctx` во всех `Extract` / `Archive`; отмена между файлами — проверить (Z5) | 6 |
| Пауза, «Фоном», время | нет | вне 12 шагов |
| Отдельное окно | одно окно на приложение (L3) | сначала строка состояния главного окна |

## Форматы

Что zipgui делает с архивом каждого вида. Таблицу в коде даёт `engine.Formats()`
(`showcase/zipgui/engine/formats.go`); тест `engine` сверяет её с этой таблицей и с самим
zipper: создаёт архив каждого формата с «Запись», дописывает в каждый с «Изменение» и читает
назад.

| Расширение | Чтение | Запись | Изменение | Пароль |
|---|---|---|---|---|
| `.zip` | да | да | да | да |
| `.tar` | да | да | да | да |
| `.tar.gz` | да | да | да | да |
| `.tar.xz` | да | да | да | да |
| `.tar.zst` | да | да | да | да |
| `.tar.bz2` | да | нет | нет | да |
| `.7z` | да | да | нет | да |
| `.rar` | да | нет | нет | да |

* Запись — новый архив через `archive.NewArchiver` (формат по расширению). RAR zipper не пишет;
  для `.tar.bz2` у пакета tar нет сжатия bzip2 на запись (только чтение).
* Изменение — `archive.NewUpdater`: zip и tar.* на месте; для 7z и rar zipper отвечает ошибкой
  «in-place updates not supported», в zipgui кнопки изменения у них неактивны (шаг 9).
* Пароль — у zip и 7z пароль на записи шифрует данные файлов; у tar.* — поток целиком; rar и
  `.tar.bz2` — только открыть архив с паролем. Проверка паролей тестами — шаг 10.
