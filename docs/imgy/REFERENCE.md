# REFERENCE — как получить и читать эталонный просмотрщик 5.6

Порядок источников (сильнейший первым):

1. **Help из дистрибутива 5.6** — основной источник списка возможностей.
2. **Запуск эталона в CI** (A3) — источник фактического вида и поведения (скриншоты).
3. **Сайт** — вспомогательный; помни, что он может описывать версии новее 5.6.
4. **Ответы пользователя** — последнее слово там, где источники молчат или спорят.

Если источники расходятся: help — про намерение, скриншот — про факт; спорное помечай `?` и спрашивай.

## 1. Что пользователь уже сделал

Установщик 5.6 выложен пользователем: `http://2g0.ru/fs/FSViewerSetup56.exe` (именно `http`).
Других зеркал сам не ищи — только с разрешения пользователя.

## 2. Скачать (A1)

1. `curl -fL --connect-timeout 20 --max-time 300 -o /tmp/FSViewerSetup56.exe http://2g0.ru/fs/FSViewerSetup56.exe`
   - Нет сети, домен запрещён (заголовок `x-deny-reason` у прокси), код ≠ 200 → **СТОП**. Скажи пользователю: «песочница не достаёт до 2g0.ru: загрузи файл в чат или добавь домен в разрешённые». Больше ничего не делай.
2. `ls -l`, `sha256sum`, `file`. Размер 0 или это HTML (страница ошибки) → **СТОП**, спроси.
3. Запиши URL, размер, sha256 в `spec/REFERENCE-NOTES.md`. Дальше CI сверяет sha256 (пин).

## 3. Распаковать (A1)

Пробуй по порядку; **первый успех побеждает**, остальные не пробуй; на каждую попытку — не более одного вызова инструмента.

1. `7z l /tmp/FSViewerSetup56.exe` — если перечисляет файлы: `7z x -o/tmp/fsv-x /tmp/FSViewerSetup56.exe`.
2. `innoextract -l …`, затем `innoextract -d /tmp/fsv-x …` (для установщиков Inno Setup).
3. Под Wine: `xvfb-run -a wine /tmp/FSViewerSetup56.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /DIR=C:\fsv` (флаги Inno; для NSIS — `/S /D=C:\fsv`).

Ставить в песочнице можно мелочь: `p7zip-full`, `innoextract`, `chmlib-tools`/`libchm-bin`. Тяжёлое (Wine целиком) — спроси.
Ни один способ не сработал → **СТОП**: приложи вывод `file`, `7z l … | head -20`, спроси пользователя.

## 4. Найти help (A1)

Ищи в извлечённом: `find /tmp/fsv-x -iname '*.chm' -o -iname '*.hlp' -o -iname '*.htm*' | head -50`.

| Что нашли | Действие |
|---|---|
| `*.chm` | `7z x help.chm -o/tmp/fsv-help` или `extract_chmLib help.chm /tmp/fsv-help`; оглавление — `*.hhc` |
| Каталог с `*.htm*` | Оглавление ищи в индексной странице |
| `*.hlp` (WinHelp) | **СТОП**, спроси пользователя (формат неудобный, нужен его совет) |
| Help нет вообще (возможно, онлайн-справка) | **СТОП**, спроси адрес страниц или попроси сохранить их |

Кодировка страниц: `file -i`; нужна — `iconv -f <кодировка> -t utf-8`. Не грузи в контекст больше ~30 КБ текста за вызов.
Сначала читай **только оглавление**, потом страницы по одной секции за ответ.

## 5. Итог A1

`spec/REFERENCE-NOTES.md` содержит: URL, размер, sha256; тип инсталлятора и чем извлекли; формат help; путь к оглавлению;
кодировку; что оказалось непонятным. Сам эталон и его файлы в репозиторий не кладём (§8).

## 6. Запуск эталона в CI (A3)

- Workflow `.github/workflows/fsref.yml`, триггер только `workflow_dispatch`, `ubuntu-latest`.
- Шаги: apt (wine, xvfb, xdotool, imagemagick) → скачать установщик → сверить sha256 → тихая установка под Wine → запуск в `xvfb-run` → сценарии из `tools/fsref/` (xdotool, скриншоты через `import -window root`) → `upload-artifact`.
- Тестовые картинки генерируй кодом (детерминированно). Чужие фотографии не бери.
- Сценарии описаны в `spec/SCENARIOS.md`: `ID сценария | что делаем | имя скриншота | ID из инвентаря`.
- Эталон не запускается под Wine → один раунд бисекции (что именно падает: установка / запуск / показ окна), затем вопрос пользователю.
- Артефакты Actions, как правило, требуют входа: скачать их модель не может. **Пользователь скачивает и прикладывает скриншоты в чат.**

## 7. Формат `spec/INVENTORY.md`

Таблица, одна строка на возможность:

| ID | Раздел help | Возможность (одной строкой, своими словами) | Статус | Приоритет | Нужно фреймворку | Проверено |
|---|---|---|---|---|---|---|
| FS-001 | … | … | in / later / out / ? | P0–P3 | Canvas, MenuBar, … | help / shot:<id> / user / ? |

- `out` без указания пользователя — только для видео. Всё остальное сомнительное — `?` и вопрос пачкой.
- Поведение, которое нельзя вывести из help однозначно, при `Проверено = ?` **не реализуется**: сначала скриншот эталона или ответ пользователя.
- Не переписывай help: ID, заголовок раздела, суть в одну строку своими словами.

## 8. Что можно коммитить

- Можно: инвентарь и сценарии своими словами, скрипты, workflow, картинки, сгенерированные кодом, названия пунктов меню и подписи (это функциональные имена).
- Нельзя (пока Q1 не решён пользователем): установщик, распакованные файлы, страницы help, скриншоты эталона, иконки и растры оттуда, крупные дословные фрагменты текста.
- Автор плана лицензию не проверял. Пользователь помнит, что редистрибуция не запрещена, — это не проверено.
