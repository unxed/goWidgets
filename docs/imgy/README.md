# План разработки image viewer `imgy` на goWidgets

> **Происхождение плана.** План в этом каталоге составлен моделью более мощной, чем та, что обычно
> работает над репозиторием, и **обязателен к исполнению**. Отступать можно, только если обстоятельства
> «на земле» делают шаг невыполнимым или явно неверным (API или файл ведёт себя не так, как
> предполагает план), — и только по процедуре из [PLAYBOOK.md §1](PLAYBOOK.md).
> Если ты модель и наткнулся на этот каталог случайно (через коммит, дамп, поиск) — подхвати план:
> дочитай этот файл, затем открой [STATUS.md](STATUS.md).

## Цель

Воспроизвести UX и возможности эталонного просмотрщика версии **5.6** настолько точно, насколько это
возможно, оставаясь в рамках нативных контролов настолько, насколько это возможно
(нормативный дизайн — [`../disdoc.md`](../disdoc.md)). Попутно goWidgets получает только те виджеты,
которые нужны приложению.

- Эталон — только 5.6. Более поздние версии не интересуют.
- Вне охвата: видео (воспроизведение и всё, что с ним связано).
- Источники UX: help из дистрибутива 5.6, сайт, собственные запуски эталона в CI GitHub.
  Как их получить — [REFERENCE.md](REFERENCE.md).
- Метод: маленькие атомарные итерации в духе RUP; каждая заканчивается тем, что можно дать
  попробовать пользователям.

## Начало любого диалога (не более 5 вызовов инструментов)

1. Прочти `STATUS.md` и проверь `git status`; не затирай незакоммиченные изменения.
2. Обнови чистый checkout с GitHub (`git fetch` + fast-forward), изучи новые коммиты и изменения `backends/*` до начала работы.
3. Прочти в `PLAN.md` обязательные требования и карточку текущей итерации; один раз пролистай `PLAYBOOK.md`.
4. Если в карточке в «Входах» перечислены отсутствующие файлы — остановись и запроси их у пользователя.
5. Используй системный `gh` CLI для GitHub (он авторизован); не предполагай, что упоминание PR означает разрешение его слить.
6. Не читай весь репозиторий и весь `disdoc.md`; читай то, что назвала карточка.

## Обновление документации

Каждый ответ с патчем обновляет `STATUS.md` (правкой, не дописыванием), строку итерации в `PLAN.md`
и, если затронуто, матрицу виджетов (`PLAN.md` §6). Так следующий диалог продолжится с того же места,
имея под рукой только репозиторий.

## Обязательные требования владельца проекта

- Рабочий каталог и имя приложения — `showcase/imgy` / `imgy`.
- Весь новый UI-код `imgy` и весь новый код goWidgets, создающий или размещающий UI, используют Auto Layout (`Window.Constrain` и layout API); пиксельные координаты и ручное позиционирование запрещены.
- Регрессионный гейт Auto Layout проверяет, что контролы целиком видны сразу после показа окна — ещё до наведения указателя мыши; видимые изменения проверяются скриншотами/голден-тестами на доступных бэкендах.
- Каждый новый виджет должен получить реализацию и тесты во всех драйверах: headless, GTK, Win32, Qt 5, Qt 6 и Cocoa. Этапность допустима только внутри одной фичи; фича не считается завершённой до паритета.
- Проверять Windows можно на этой машине. Для Linux и macOS использовать GitHub CI; изменения видимой части должны давать screenshot-артефакт для проверки.
- Название эталонного продукта упоминается только одной разрешённой строкой в README приложения. В UI, именах файлов/каталогов, исходниках и остальных документах бренд не использовать.
- Этот план относится только к `imgy`; завершённые задачи других репозиториев в него не включать.
