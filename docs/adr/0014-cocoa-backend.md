# ADR-0014. Cocoa-бэкенд: AppKit через рантайм Objective-C, клавиши как в Wine

* Статус: принято
* Дата: 2026-09-29
* Затрагивает: §3.3 (darwin→cocoa), §4.4, ADR-0008 (Tab), ADR-0013

## Контекст

§3.3 с самого начала называет драйвер по умолчанию для macOS — `cocoa`, но
его не было. Мака у автора нет; проверять приходится на macOS-раннере
GitHub Actions: у него есть залогиненная GUI-сессия, так что окна, алерты,
панели и значок в строке меню там настоящие.

## Решение

`backends/cocoa` — AppKit через рантайм Objective-C и purego (подпакет
`objc` из pureffi), без CGO и без ObjC-шима.

* **Сообщения** — `objc_msgSend`; аргументы раскладываются по их Go-типам,
  так что `CGFloat` идёт в регистр с плавающей точкой, а `NSRect` — как
  агрегат из четырёх double (HFA в d0–d3 на arm64; для возврата крупной
  структуры на amd64 — `objc_msgSend_stret`).
* **Свои классы** регистрируются во время выполнения, методы — Go-функции:
  `GoWidgetsTarget` (цель всех действий, делегат окна, полей и таблицы,
  источник данных таблицы), `GoWidgetsView` (content view, перевёрнутый:
  начало координат слева сверху, как в ядре), `GoWidgetsWindow`
  (`sendEvent:` видит все клавиши окна). Вызов `super` делается через
  `objc_msgSendSuper2` с явно указанным нашим классом: AppKit подставляет
  окнам динамические подклассы (KVO), и «суперкласс класса объекта» снова
  оказывается нашим — первый прогон в CI упал на бесконечной рекурсии.
* **Главный поток.** AppKit живёт только на нём. Пакет лочит главную
  горутину на главный поток в `init`, `Init` проверяет `pthread_main_np` и
  отказывает с понятной ошибкой, если `NewApp` вызван не из `main`.
* **Wake** — `dispatch_async_f` на главную очередь: чистый C, безопасно из
  любого потока, и главная очередь обслуживается в common modes run loop'а,
  то есть и внутри модальных циклов алертов и панелей. Выход —
  `[NSApp stop:]` плюс пустое событие, без которого `stop:` не срабатывает.
* **Раскладка** — `setFrame:` по прямоугольникам ядра, которые считаются
  alignment rect'ами: `intrinsicContentSize` меряет именно их, а
  `frameForAlignmentRect:` добавляет место под тень кнопки. Tab — родной
  `autorecalculatesKeyViewLoop`: сверху вниз, слева направо, как требует
  ADR-0008.
* **Контролы**: `NSTextField` (метка и поле), `NSButton` (кнопка и
  флажок), `NSComboBox` / `NSPopUpButton` (с полем и без — как у GTK,
  вариант без поля подменяется до элементов), `NSTableView` в
  `NSScrollView` (список; двойной клик и Enter — «открыть»), `NSTextView`
  (журнал: только чтение, моноширинный, без переноса). Главное меню с
  пунктом Edit: без него Cmd+C/Cmd+V в поле ввода не работают.
* **Диалоги** — `NSAlert` и `NSOpenPanel`/`NSSavePanel` модально. Подписи
  кнопок берутся из переводов AppKit, где они там есть; на англоязычном
  раннере это не проверить.
* **Трей** — `NSStatusItem`. Меню не закреплено за значком: левый клик —
  `Activated`, правый (или Control-клик) открывает меню, как в GTK и Win32.

### Клавиши — как в Wine

Перевод в `KeyEvent` (формат `INPUT_RECORD`) повторяет Mac-драйвер Wine
(`dlls/winemac.drv`):

* таблица `default_map` Wine: для каждого из 128 кодов клавиш Mac —
  виртуальная клавиша и скан-код набора 1 той PC-клавиши, что стоит на
  том же месте (0x100 — расширенная); таблица сверена с исходником Wine
  построчно;
* клавиши, печатающие букву или цифру, берут виртуальную клавишу из
  раскладки (на AZERTY клавиша на месте Q — `VK_A`), как Wine делает для
  своих «нефиксированных» клавиш;
* модификаторы — по умолчанию как в Wine: **Command — это Alt**, Option
  печатает символы и модификатором не считается, Control — Ctrl.

Распространённая перестановка — Command как Ctrl, чтобы Cmd+C, который
жмёт маковод, доходил до программы как Ctrl+C, — настраивается теми же
четырьмя переключателями, что и в Wine (`LeftOptionIsAlt`,
`RightOptionIsAlt`, `LeftCommandIsCtrl`, `RightCommandIsCtrl`): в коде —
`goWidgets.SetMacKeyboard`, у пользователя — переменная
`goWidgets_MAC_KEYBOARD=LeftCommandIsCtrl,RightCommandIsCtrl`, как у Wine
реестр. Сами модификаторы тоже приходят событиями (FlagsChanged), с
учётом тех же настроек.

## Проверено

* `backends/cocoa/keymap_test.go` (на любой платформе): буквы, AZERTY,
  Command как Alt и как Ctrl, Option как символ и как Alt, расширенные
  клавиши, модификаторы отдельно.
* macOS-раннер GitHub (`backends/cocoa/cocoatest`, arm64): раскладка и
  resize, вето закрытия, клик; CheckBox; Edit — набор через field editor,
  Enter; клавиши окна по правилам Wine и с перестановкой; ComboBox оба
  варианта; ListBox; TextView; модальные алерты и панель сохранения;
  значок в строке меню. Снимок окна с контролами — артефакт CI.

## Не проверено и не сделано

* amd64 (Intel-маки) не запускался; код тот же, отличается только
  `objc_msgSend_stret`, который выбирает pureffi.
* `NSOpenPanel` нельзя направить на файл из теста публичным API — тест
  проверяет только отмену.
* Перевод подписей Yes/No/Cancel на русском macOS не видел.
