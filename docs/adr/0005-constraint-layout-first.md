# ADR-0005. Layout — только Cassowary, и с самого начала

* Статус: принято
* Дата: 2026-09-10
* Затрагивает: §4.3, §5, §8 (Фаза 2)

## Контекст

ADR-0004 отложил Cassowary «на потом», потому что для вертикального стека
из пяти контролов он не нужен. Опыт vtui показал цену такого решения: когда
констрейнты добавляются в конце, все уже свёрстанные диалоги остаются на
старом механизме, и библиотека живёт с двумя layout-системами и техдолгом
по их согласованию. Поэтому Фаза 2 закрывается сейчас, пока диалог один.

## Решение

1. **Один движок.** Solver — `github.com/unxed/kiwi-go` (Cassowary). Каждый
   узел — четыре переменные (`Left`, `Top`, `Width`, `Height`); `Right`,
   `Bottom`, центры — выражения над ними. Размер окна — edit-переменные,
   resize — инкрементальный `SuggestValue`, а не пересборка системы.
2. **Стек — это констрейнты.** Отдельного `stackLayout` больше нет. Виджет,
   не являющийся *субъектом* ни одного пользовательского констрейнта
   (субъект — владелец левого якоря), укладывается «потоком»: под предыдущим
   таким же, во всю ширину, отступ 8 DIP. Поток — набор medium-констрейнтов
   в том же solver'е. Golden-тест стека не изменился ни на цифру.
3. **Публичный API** (`layout.go`): `Box` с восемью якорями у каждого
   виджета и у окна; `Anchor.Eq/Ge/Le/Is/AtLeast/AtMost`, `Plus/Minus/Times`;
   `Constraint.Required/Strong/Medium/Weak`; `Window.Constrain/Unconstrain`;
   сахар `Column`, `Row`, `EqualWidths`, `EqualHeights`, `Fill` — обычные
   констрейнты, ничего скрытого.
4. **Иерархия сил** (§5.3, уточнена): required — минимальные размеры и то,
   что пользователь объявил required; «окно» (1000·strong) — размер окна,
   пользовательский констрейнт не может его изменить; strong — пользовательские
   по умолчанию; medium — поток, `PrefHeight` и схлопывание скрытого виджета;
   weak — естественные размеры.
5. **Скрытый констрейнтный виджет** схлопывается до нуля по тем осям, которые
   strong-правила оставляют свободными: в `Column` строка теряет высоту, но
   сохраняет выровненную ширину, и всё под ней поднимается. Зазор цепочки
   остаётся — констрейнт про него никто не снимал. Скрытый виджет потока
   покидает поток целиком (как и раньше).
6. **Конфликты** (§5.3): неразрешимый (required против required) констрейнт
   отбрасывается, пишется в `Diagnostics().LayoutConflicts` и возвращается
   из `Constrain` ошибкой, оборачивающей `core.ErrUnsatisfiable`; остальные
   остаются в силе. В сборке `-tags goWidgets_debug` — паника с текстом
   констрейнта. Молчаливого зависания нет: solver не итерирует до сходимости,
   а отвечает ошибкой.

## Последствия

* `go.mod`: `go 1.26` (требование kiwi-go), CI поднят до Go 1.26.
* Showcase crescent свёрстан констрейнтами: статус, колонка целей, три
  равные кнопки по нижнему краю. Это первый и с этого момента единственный
  способ верстать диалоги.
* `LayoutBoundary`, вложенные контейнеры и `bench/layout` из §5.2 — не
  сделаны; появятся, когда их потребует showcase.

## Альтернативы

* Отложить до FastStone (как в ADR-0004) — отвергнуто по причине из «Контекста».
* Поток как отдельная ветка кода для «неконстрейнтных» окон — отвергнуто:
  это ровно две layout-системы.
* Убрать поток совсем, требовать констрейнты всегда — отвергнуто: окно без
  единого правила должно что-то показывать, а не сложить всё в (0,0).
