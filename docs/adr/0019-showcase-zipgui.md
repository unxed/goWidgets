# ADR-0019. Showcase `zipgui`: графический архиватор на движке zipper

* Статус: принято
* Дата: 2026-10-20
* Затрагивает: §2.7 (showcase-driven), §1.3 (NFR: размер бинаря), §10 («новые зависимости — только через ADR»), ADR-0004

## Контекст

§2.7 требует развивать библиотеку через живые showcase. У crescent и pixy (ADR-0004) нет
табличных данных, навигации по иерархии, долгих фоновых операций с прогрессом и отменой,
многостраничных диалогов и drag-and-drop файлов. Всё это нужно архиватору с UX уровня
WinRAR: список с колонками и сортировкой, строка пути внутри архива, панель команд,
окна прогресса, диалоги «Добавить» и «Извлечь».

Движок уже есть — пакет `github.com/unxed/zipper/archive` (zip, tar.*, 7z и rar на чтение).
Тянуть его в модуль библиотеки нельзя без последствий: zipper приносит около тридцати модулей
(zip, tar, sevenzip, rardecode, par2, SQLite на wazero и т. д.), и каждый пользователь
`github.com/unxed/goWidgets` увидел бы их в графе зависимостей, а каждый выпуск zipper
менял бы `go.mod` библиотеки.

## Решение

1. **Имя и место.** Showcase называется `zipgui`, каталог `showcase/zipgui`, бинарь `zipgui`.
   Эталон UX — WinRAR; в интерфейсе и в коде имя эталона не используется, только в документах
   `docs/zipgui/`.
2. **Отдельный модуль.** `showcase/zipgui` — вложенный Go-модуль
   `github.com/unxed/goWidgets/showcase/zipgui` с `replace github.com/unxed/goWidgets => ../..`.
   Модуль библиотеки зависимостей zipper не получает. Вложенный модуль обязан повторять
   `replace` библиотеки (`github.com/ebitengine/purego => github.com/unxed/pureffi`): директивы
   `replace` зависимостей Go не применяет.
3. **Граница с движком.** Только пакет `showcase/zipgui/engine` импортирует
   `github.com/unxed/zipper/archive`; окно (`package main`) говорит с движком через него.
   Так пробелы API zipper видны в одном месте и закрываются в zipper, а не обходами в UI.
4. **Движок в том же процессе.** CLI zipper не запускается и не меняется. Чего не хватает в
   `zipper/archive` (метаданные листинга, извлечение выбранного, проверка, запрос при
   перезаписи) — отдельный тикет и PR в unxed/zipper.
5. **Инварианты библиотеки действуют без исключений:** `CGO_ENABLED=0`; вся геометрия — общий
   constraint layout; новый контрол — во всех бэкендах либо capability-флаг с запасным путём в
   core; из фоновой горутины виджеты трогаются только через `App.QueueUpdate`.
6. **CI.** Корневые `go vet ./...` и `go test ./...` вложенный модуль не видят, поэтому
   `CI fast` проверяет его отдельным шагом: `go mod tidy -diff`, vet (linux и windows), тесты,
   кросс-сборка на все цели crescent/pixy и проверка NFR «бинарь showcase < 25 МБ».
   `CI gui` собирает его на Windows и macOS и гоняет тесты под Xvfb на Linux. Скриншоты — в
   артефакты CI.
7. **Чередование с pixy.** План pixy (`docs/pixy/`) не вытесняется: шаги zipgui чередуются с ним,
   одновременно открыт не больше одного PR zipgui. План — `docs/zipgui/PLAN.md`.

### Что берём из WinRAR и чего не берём

Берём: главное окно (панель Add / Extract To / Test / View / Delete / Find / Info, строка пути,
список Name / Size / Packed / Type / Modified / CRC, строка состояния), навигацию внутри архива,
диалоги Add и Extract в объёме того, что умеет zipper, прогресс с отменой, пароли, проверку
архива, drag-and-drop файлов, сводку и поиск.

Не берём (позже — отдельными тикетами, если понадобится, или никогда): интеграцию с оболочкой
ОС (контекстное меню проводника), мастер SFX, создание RAR (zipper его не пишет), комментарии
архива, темы оформления, планировщик и избранное, восстановление RAR (у zipper своё PAR2-
восстановление для zip и tar — возможно, отдельным шагом после 12-го).

## Последствия

* Библиотека получает от zipgui заявки на таблицу с колонками, индикатор прогресса,
  модальные окна, маскированный ввод и приём файлов перетаскиванием — каждую через свой шаг
  плана и, где меняется контракт драйвера, свой ADR.
* Обновление zipper — правка `showcase/zipgui/go.mod`, библиотеку не трогает.
* Вложенный модуль легко забыть: любой новый шаг CI для showcase добавляется явно для
  `showcase/zipgui`.

## Альтернативы

* Showcase в модуле библиотеки, как pixy, — отвергнуто: граф зависимостей библиотеки растёт на
  порядок ради одного примера, `go.mod` библиотеки меняется с каждым выпуском zipper.
* Запускать CLI zipper и разбирать его вывод — отвергнуто постановкой (unxed/goWidgets#30):
  нет прогресса и отмены без разбора текста, а CLI менять нельзя.
* Отдельный репозиторий (как crescent) — отвергнуто: showcase должен проверять API библиотеки
  в том же PR, где API меняется.
