# Для ИИ-ассистентов и новых участников

Работа над showcase `pixy` (и над фреймворком ради него) ведётся по плану в
[`docs/pixy/`](docs/pixy/README.md). План составлен моделью более мощной, чем та, что
обычно работает над этим репозиторием, и **обязателен к исполнению**; отступать можно только по
процедуре из [`docs/pixy/PLAYBOOK.md`](docs/pixy/PLAYBOOK.md) §1.

Начни с `docs/pixy/README.md`, затем `docs/pixy/STATUS.md`.

Всегда действуют: нормативный дизайн `docs/disdoc.md` и решения `docs/adr/`.
Файл `filelist.md` вручную не править — его пишет другой процесс.

## CI и протокол параллельных агентов

Под одной учёткой работают несколько агентов; CI не должен быть узким местом.

- Два workflow: `CI fast` (gofmt, vet, тесты без дисплея, кросс-сборка; ~1–2 мин)
  и `CI gui` (Xvfb/Wine/Cocoa-тесты, скриншоты; только при изменениях `**.go`,
  `go.mod`/`go.sum`, `tools/ci/**`, `ci/**`). Docs-only пуши (`**.md`, `docs/**`,
  `spec/**`) CI не запускают.
- Общая concurrency-группа `ci-<ref>`; PR-прогон отменяет дублирующий push-прогон
  той же ветки. Прогоны `main` не отменяются.
- Один агент — одна ветка `agent/<имя>/<тема>`; в `main` — только через PR.
  `CI fast` обязателен к зелёному до ревью; `CI gui` догоняет асинхронно.
- Перед пушем локально: `gofmt -l .`, `go vet ./...`, `go test -count=1 ./showcase/pixy/...`.
- Ветка `main` защищена (branch protection, required checks: `fast`, `linux`,
  `windows`, `macos`); сливает владелец.
